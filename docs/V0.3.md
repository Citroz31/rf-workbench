# RF Workbench 0.3 — Studio RF

Cette version enrichit l'application Rust existante avec un éditeur de banc, des vues RF dockables et un débogueur du flux. Les 18 blocs illustrés, les transports Rust et la passerelle Python restent disponibles. La livraison est un prototype Windows ; la qualification sur instruments, les installateurs et les applications mobiles restent à développer.

## Construire et manipuler le banc

La palette regroupe les blocs par métier, avec **Favoris**, **Récents** et recherche floue. Elle accepte les sous-séquences et les alias ADC/CAN, DAC et IQ. Cliquer ajoute un bloc ; le clic droit propose favori et aide. Les huit derniers types utilisés sont conservés dans Studio.

**V** active la sélection. **Shift+clic** ajoute ou retire un bloc, et glisser le fond crée un rectangle de sélection. Le déplacement d'un groupe conserve les positions relatives, puis applique la grille de 24 unités si elle est activée. **Édition** propose alignement gauche/haut, distribution horizontale/verticale, organisation selon le flux et routage des câbles.

Le routage cherche des chemins orthogonaux qui évitent les rectangles des blocs, avec marge et sorties de connecteurs. Les calculs d'ensemble et l'organisation s'effectuent dans un thread distinct. Un résultat est ignoré si le graphe a changé entre-temps. Les régions trop denses, les connecteurs obstrués et les parcours trop complexes produisent un message ; déplacer les blocs ou placer des coudes reste possible. Le routage local est borné à 96 obstacles et 64 coudes par câble. Aucun routage physique d'instrument n'est effectué.

**W** démarre le câblage : sortie, éventuellement clics sur le fond pour les coudes, puis entrée compatible. **Échap** annule. Les parcours automatiques sont recalculés après le déplacement des blocs ; les parcours manuels sont conservés. **H** ou le bouton central déplace le canevas ; molette pour zoomer ; **F** ajuste le cadrage.

**Ctrl+C / Ctrl+V** utilisent le presse-papiers système pour les blocs sélectionnés et leurs connexions internes. Les identifiants sont recréés au collage. **Ctrl+D** duplique la sélection. Les annotations sont des notes déplaçables et éditables dans l'inspecteur ; chaque bloc possède aussi un commentaire sauvegardé dans le projet. La sélection par rectangle concerne les blocs ; le copier/coller ne transporte pas les notes libres.

L'historique du graphe n'a plus de plafond fixe de 100 actions. Il couvre paramètres, commentaires, annotations, connexions et déplacements, et appartient à chaque espace de travail. Il reste en mémoire pendant la session, jusqu'à la fermeture de l'espace ; sa taille dépend donc de la mémoire disponible. Il n'est pas sérialisé dans le fichier Studio.

## Disposer les vues

Le menu **Vues RF** ouvre les analyses. Le menu **Disposition** de chaque vue permet de choisir **Principale**, **À droite**, **En bas**, **Flottante** ou **Masquée**. Les régions latérales et inférieures se redimensionnent ; plusieurs vues y deviennent des onglets. Les fenêtres flottantes se déplacent par leur barre de titre. Le placement s'effectue par ces menus, sans glisser-déposer d'onglets.

| Vue | Données et réglages disponibles |
| --- | --- |
| Graphe | Blocs, ports nommés, sélection, parcours, annotations, états de debug |
| Spectre | Dernière trace complète, dBm/Hz, pic, marqueur et export CSV |
| Paramètres S | Magnitude dB et phase en degrés du dernier PNA exécuté |
| Mesures | Valeurs scalaires avec unité et provenance |
| Waterfall | Jusqu'à 128 acquisitions compatibles ; maximum de 512 colonnes avec conservation des pics |
| Constellation | Choix de deux buffers I/Q, même longueur, unité et cadence ; trajectoire ou décimation par symbole |
| Smith | S11/S22 complexes et impédance de référence Z0 réglable ; survol fréquence, réflexion et impédance |
| Eye diagram | Choix d'un buffer, échantillons/UI et offset ; repliement sur deux UI |
| Chronogramme | Choix d'un buffer, seuil dans son unité et représentation 0/1 |
| Débogage | Bloc courant, commandes d'exécution, sorties par port et inspection des valeurs |

La waterfall accumule les acquisitions reçues, sans créer de lignes artificielles ; elle repart à zéro si la grille de fréquences change. Son axe vertical représente les acquisitions, sans supposer une cadence uniforme. Les plots principaux conservent la dernière acquisition complète. Les buffers du débogueur sont actualisés entre blocs.

La constellation n'effectue ni synchronisation ni calcul d'EVM. La démonstration AWG fournit des sinusoïdes I/Q : leur trajectoire est un cercle, pas une constellation QAM fabriquée. Le diagramme de l'œil utilise la cadence symbole saisie ; il n'effectue pas de récupération d'horloge. Le chronogramme représente un seuillage, sans décodage de protocole. Ces analyses utilisent les prévisualisations bornées des buffers : leur taille affichée peut être inférieure à l'acquisition complète.

Le Smith reconstruit `Gamma = 10^(magnitude_dB/20) * exp(j * phase)` puis `Z = Z0 * (1 + Gamma) / (1 - Gamma)`. S21/S12 sont refusés comme coefficients de réflexion. Une impédance infinie au voisinage de Gamma = 1 est indiquée explicitement. Voir la [documentation Keysight sur impédance et réflexion](https://helpfiles.keysight.com/csg/pxivna/Tutorials/Comp_Imped.htm) et les [principes de constellation I/Q de MathWorks](https://www.mathworks.com/help/comm/ref/constellationdiagram.html). Les modèles PNA demeurent simulés, sans calibration ni mesure qualifiée sur matériel.

## Déboguer

1. Cocher **Breakpoint** et/ou **Sonde** dans l'inspecteur, ou utiliser le clic droit du bloc.
2. **F6** ou **Démarrer le debug** prend un instantané du graphe et s'arrête avant le premier bloc.
3. **F10 / Pas à pas** exécute un bloc ; **F8 / Continuer** avance jusqu'au prochain breakpoint ou à la fin.
4. Choisir une sortie dans le panneau Debug pour inspecter fréquence/niveau, vecteur, paramètres S, modèle DUT ou scalaire avec unité. **Sondes uniquement** filtre les sorties marquées.
5. **Arrêter** annule aussi une exécution en pause.

L'inspection montre les valeurs produites par le moteur, leur provenance et leur taille d'origine. Les tableaux sont limités aux 4096 premiers échantillons ; 512 ports au plus sont conservés, en donnant priorité aux sondes. Les buffers sont immuables et partagés par `Arc`, et le dernier état remplace le précédent pour éviter une file croissante.

Le debug est réservé aux graphes simulés : toute ressource physique est refusée avant exécution. Le pas est un **bloc entier**, y compris pour Python ; aucun débogage ligne par ligne Python ni pas dans le pilote instrument n'est fourni. Les modifications faites pendant le debug ne changent pas l'instantané lancé ; relancer pour les appliquer.

## Espaces, sauvegarde et apparence

**Espaces de travail** permet de créer jusqu'à huit bancs et vingt layouts nommés. Les onglets en haut changent de banc. Chaque espace conserve son projet, ses chemins de fichiers, son cadrage, son layout et ses résultats/historique de session. Un nouvel espace reçoit des chemins distincts. Le changement d'espace est désactivé pendant une exécution.

**Enregistrer Studio** écrit atomiquement `studio.rfw.json` dans le dossier de travail et conserve projets, disposition des vues, tailles, position des fenêtres flottantes, cadrage, favoris, récents, thème et langue. Le fichier est restauré au démarrage. Les résultats, buffers, waterfall et historiques sont conservés en mémoire lors du changement d'espace, puis perdus à la fermeture de l'application. Exporter les mesures et sauvegarder les projets pour les conserver indépendamment. Il n'y a pas encore de sauvegarde automatique ni de récupération après crash.

Les réglages offrent thème clair/sombre, contraste renforcé, taille de texte de 85 à 150 % et français/anglais pour la navigation, les commandes principales et l'aide. Les titres utilisateur, scripts, commandes SCPI et erreurs techniques ne sont pas réécrits. Les widgets egui disposent d'AccessKit ; les ports portent leurs noms et unités, et PASS/FAIL reste textuel. La navigation du graphe se fait après avoir cliqué le canevas : **Tab / Shift+Tab** parcourt les blocs, **← / →** choisit un port et **Entrée** démarre ou termine une connexion. Cliquer un autre panneau rend sa navigation clavier native. Les raccourcis sont suspendus dans les champs de texte.

La navigation au clavier et les réglages d'affichage ne constituent pas une validation complète avec lecteur d'écran, DPI multiples ou matériel tactile. iOS/Android restent au stade d'architecture.

## Aide et raccourcis

**F1** ouvre l'aide globale : construction, édition, navigation, disposition, mesures, debug et accessibilité. **F2**, le bouton **Aide du bloc** ou le clic droit ouvre la documentation du bloc sélectionné. Les 18 fiches présentent usage, ports, formules, exemple et limites en français/anglais.

| Action | Raccourci initial |
| --- | --- |
| Sélection / Câblage / Déplacement / Cadrage | V / W / H / F |
| Exécuter / Arrêter | F5 / Shift+F5 |
| Annuler / Rétablir | Ctrl+Z / Ctrl+Y |
| Sélectionner tout / Copier / Coller / Dupliquer | Ctrl+A / Ctrl+C / Ctrl+V / Ctrl+D |
| Organiser / Router | Ctrl+L / Ctrl+R |
| Ajouter une annotation | Ctrl+Shift+A |
| Debug / Pas / Continuer | F6 / F10 / F8 |
| Aide globale / Aide du bloc | F1 / F2 |
| Configurer les raccourcis | Ctrl+K |

Les 28 actions acceptent plusieurs combinaisons. La migration des préférences 0.2 préserve les raccourcis utilisateur ; un nouveau raccourci qui entrerait en conflit reste vide et peut être défini dans les réglages.

## Architecture et validation

`editor` gère recherche, sélection, collage, alignement et routage ; `studio` valide la persistance ; `analysis` trace les buffers ; `help` et `i18n` fournissent la documentation et les libellés ; `rf-runtime::debug` décrit les sorties et étapes. Le worker possède toujours les instruments et le processus Python. L'interface n'effectue pas de transfert physique dans sa boucle de rendu.

La validation couvre le passage réel de bloc en bloc, les breakpoints, l'arrêt en pause, le refus du debug physique, les unités/provenances, la compatibilité des projets 0.2, le routage autour d'un obstacle, les parcours manuels, la sélection/déplacement groupé et le câblage clavier par événements egui. Voir [VALIDATION.md](VALIDATION.md) pour les contrôles réalisés et leurs limites. Aucun objectif de latence temps réel ni profil de 1000 blocs n'est déclaré atteint.
